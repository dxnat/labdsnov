# Colors (สี)

## Purpose

สีทั้งหมดของระบบเป็น token ใน `src/styles/theme.css` มีค่าสำหรับโหมดสว่างและโหมดมืด ห้ามใช้ค่าสีตรง ๆ (เช่น `#f97316` หรือ `oklch(...)`) ในคอมโพเนนต์หรือหน้าจอ

## Two layers of tokens

1. **Semantic tokens** (หน้านี้): สีตามความหมาย เช่น `--primary`, `--muted-foreground`, `--destructive` เปลี่ยนที่นี่แล้วทุกคอมโพเนนต์เปลี่ยนตาม
2. **Component tokens** (ดู [Component tokens](./ComponentTokens.md)): สีของแต่ละส่วนของคอมโพเนนต์ เช่น `--button-primary-bg` ชี้ไปที่ semantic token เปลี่ยนเพื่อปรับคอมโพเนนต์เดียว

ทุกคู่สีที่ใช้จริงผ่าน WCAG 2.2 AA ทั้งสองโหมด ดู [Accessibility](./Accessibility.md)

## How to use

- **ในแอปที่ใช้ Tailwind**: `bg-(--primary)`, `text-(--muted-foreground)` ใช้ได้เสมอ ส่วนชื่อสั้น (`bg-primary`) ต้องมี `@theme inline` ในแอป (ดู [Getting started](./GettingStarted.md))
- **ใน CSS ปกติ**: `color: var(--muted-foreground)`
- **ตัวอักษรต้องคู่กับพื้นของมัน**: บน `--primary` ใช้ `--primary-foreground`, บน `--card` ใช้ `--card-foreground` ไม่จับคู่ข้ามกัน
- **`--destructive` / `--success` / `--warning`** ใช้เป็นสีตัวอักษร หรือเป็นพื้นจาง (10% ในโหมดสว่าง, 20% ในโหมดมืด) คู่กับตัวอักษรสีเดียวกัน ไม่ใช้เป็นพื้นทึบใต้ตัวอักษรขาว
- **`--border` vs `--control-border`**: `--border` สำหรับเส้นตกแต่ง (ขอบ Card, เส้นคั่น, ตาราง) ส่วนขอบที่บอกว่า "ตรงนี้คือช่องกรอก/ตัวเลือก" ต้องใช้ `--control-border` ซึ่งเข้มพอ (3:1)
- **อย่าบอกความหมายด้วยสีอย่างเดียว**: สถานะ เช่น ความเสี่ยงสูง ต้องมีข้อความหรือไอคอนด้วยเสมอ

## Dark mode

- ใส่ class `dark` ที่ `<html>` (เช่น `next-themes` ด้วย `attribute="class"`) ทุก token เปลี่ยนเป็นค่าโหมดมืดเอง
- ใส่ `dark` ที่ element ย่อยก็ได้ ส่วนนั้นจะเป็นโหมดมืดทั้ง semantic และ component token
- ในโหมดมืด `--primary` สว่างขึ้นและ `--primary-foreground` เป็นสีเข้ม เพื่อให้ปุ่มหลักและตัวเลือกที่เลือกแล้วเห็นชัดบนพื้นมืด

ตารางในหน้านี้สร้างจาก `theme.css` ด้วย `pnpm tokens:docs` อย่าแก้ในตารางโดยตรง
